Tiqora vs Znuny, OTRS, Zammad, FreeScout & osTicket

For teams running OTRS or Znuny today, and for anyone choosing a self-hosted helpdesk: what each option does, what it costs you in licensing and migration effort, and where it is the better pick.

Fair warning: we build Tiqora, and Tiqora is young — the first public release was in September 2026. This comparison reflects what we could verify in each product's own docs, sites and repositories as of October 2026. Every competitor claim links to a source; where we could not verify something, the cell says “—”. Corrections are welcome in GitHub Discussions.

The short version

Six tools, three very different starting points.

You run OTRS 6 / Znuny 6.0–7.3

Tiqora or stay on Znuny

Tiqora runs on your existing database next to Znuny, so you can try a modern UI and AI assistance without a data migration. Znuny itself remains the safe choice if you depend on ITSM/CMDB packages, the stats framework or custom OPM add-ons.

Greenfield, many channels

Zammad is the mature all-rounder

Long track record, a broad channel list (chat, social, phone, messaging), hosted and self-hosted editions and commercial support. Tiqora is stronger on PII masking, PGP/S/MIME depth and OTRS/Znuny compatibility.

Small team, shared inbox

FreeScout or osTicket

Lightweight PHP apps that run almost anywhere. FreeScout keeps the core small and sells modules; osTicket is a classic, simple ticket system. Both are easier to operate than any OTRS-derived system.

Where the others are stronger

If one of these points decides it for you, take it seriously.

Znuny

  • Free ITSM bundle (CMDB, change, incident/problem) and a large OPM add-on ecosystem.
  • Full statistics framework and a graphical process designer.
  • Native SAML (7.3) and a long LTS track record; commercial services from Znuny GmbH.

OTRS

  • Commercial vendor with support included, managed SaaS or on-premise.
  • ITSM, CMDB and process engine from one vendor.
  • Rule-based anonymization, pseudonymization and deletion for data privacy.

Zammad

  • Maturity and a large open-source community.
  • Channel breadth: web chat, Facebook, SMS, Telegram, WhatsApp, Microsoft 365/Google mail, several CTI integrations.
  • SAML, many social logins, hosted and self-hosted editions, support contracts.

FreeScout

  • Very light: PHP and a database, no minimum hardware requirements stated.
  • Shared-inbox workflow that small teams pick up in minutes.
  • Pay only for the modules you need; a free official AI module.

osTicket

  • Simple, long-established ticket system that runs on almost any PHP host.
  • SLAs, help topics and a customer portal out of the box.
  • Hosted edition with vendor support if you do not want to run it yourself.

Tiqora's own gaps

  • Missing: saved searches, configurable dashboards, link overview, several admin screens (sessions, SQL box, maintenance, system log), calendar admin, portal print view.
  • Partial: statistics, GenericAgent, bulk actions, preferences, GenericInterface edge cases, process conditions/actions.
  • By design: no OPM Package Manager, process designer, SysConfig editor or webservice editor.
  • Not yet: SAML, web chat widget, social channels, ITSM/CMDB.

Why Tiqora if you run Znuny or OTRS today

Most helpdesk switches are big-bang migrations: export, transform, import, retrain, hope. Tiqora skips the data migration entirely.

  1. Same database

    Point Tiqora at your OTRS 6.0.x or Znuny 6.0–7.3 database (MariaDB/MySQL or PostgreSQL). It detects the schema version and only adds its own tiqora_* tables.

  2. Run both side by side

    Znuny keeps processing mail, escalations, notifications and GenericAgent. Agents can try Tiqora on live tickets while everyone else keeps working in Znuny.

  3. Hand over flag by flag

    Move daemons one at a time with feature flags, off by default. Ticket numbers, history and escalation columns stay readable by Znuny the whole time.

  4. Cut over when ready

    Retire Znuny only at the end, following the cutover runbook. Until then you can step back at any stage.

When another tool is the better choice

We would rather you pick the right tool than the wrong one.

You need ITSM / CMDB

Configuration items, change management and ITIL processes: stay on Znuny with its free ITSM packages, or look at OTRS. Tiqora has no CMDB.

You depend on custom OPM add-ons

Tiqora cannot run Perl OPM packages. If your workflows live in add-ons, Znuny is the safe home — or run Tiqora alongside and keep those parts in Znuny.

You want a vendor contract and SLA today

OTRS, Zammad and Znuny GmbH sell support and hosting. Tiqora is a young open-source project; support today means GitHub issues and Discussions.

You need web chat or social channels

A website chat widget or Facebook: Zammad covers these out of the box. Tiqora has neither today.

You need SAML or deep reporting

SAML-only identity providers or configurable, scheduled statistics: Znuny 7.3, Zammad or OTRS.

You are a three-person team on shared hosting

FreeScout or osTicket run on any PHP host. Tiqora needs Docker, Redis and Meilisearch.
